# Folia 内置 baoyu-diagram 成品图规格 v1

来源：`JimLiu/baoyu-skills` 的 `baoyu-diagram`，上游版本 `1.117.3`，核对提交
`6b7a2e417500561a5ecdd0b168332f4142584617`。Folia 仅使用本文件锁定的 SVG
生成子集，不读取或执行用户机器上的其他 Skill。许可证见
`THIRD_PARTY_LICENSES/baoyu-skills-MIT.txt`。

## 目标

把输入 Markdown 忠实整理成一张专业、可直接交付的自包含 SVG。优先保证中文可读、
信息层级清楚、连接关系准确和留白舒适；不要为了装饰牺牲事实表达。

## 支持的图类型

- `flowchart`：自上而下的流程图。主流程居中，分支向左右展开；开始/结束用大圆角框，
  操作用矩形，判断用菱形，分支箭头标明“是/否”或准确条件。
- `timeline`：按日期或阶段排列的时间轴。事件说明交错放在轴线两侧，避免文字重叠；
  没有明确日期时不得编造日期，可改用“阶段一/阶段二”等原文已有顺序。
- `relationship`：人物、机构、证据或概念关系图。先分组再布局，连接线必须标注关系；
  边从节点边缘出发，标签与节点和其他连接线保持间距。
- `mindmap`：中心主题向外辐射的脑图。一级分支数量保持克制，使用曲线连接，文字越长
  节点越宽；不得让标题、分支或说明互相覆盖。

## 通用布局规则

1. 成品图是信息导航，不是全文副本。先识别核心节点、分组和关系，再计算画布；一般保留
   8-16 个核心节点，特别复杂的材料最多 20 个。重复论据、同类细节和长段解释合并为短句，
   但姓名、日期、金额、原文引述和关系不得改写或编造。
2. 标题距离画布边缘至少 24px，图形内容与标题至少 28px。
3. 标准节点高度 52-72px；复杂节点可到 96px。节点水平间距至少 32px，垂直间距
   至少 44px；箭头标签距离节点边缘至少 10px。
4. 连接线先画，节点遮罩与节点本体后画，文字最后画，保证线条不会穿过文字。
5. 优先使用直线、折线或平缓曲线，避免无意义交叉；必须交叉时调整分组或扩大画布。
6. 根据中文长度扩大节点。正文不得小于 12px，说明不得小于 10px，标题 22-28px。
7. `viewBox` 必须包住所有内容，并在四周至少保留 30px；不要设置固定 `width` 或
   `height`，让 SVG 自适应缩放。

## 风格

只使用任务参数指定的一种风格：

- `light-formal`（浅色正式）：暖白纸面，深灰正文，赭色作为唯一强调色；细边框、
  轻分区、克制圆角，适合法律文书和正式报告。
- `business`（简洁商务）：冷白或浅灰纸面，炭黑正文，低饱和钢蓝灰用于层级区分；
  网格清楚，装饰最少。
- `dark-tech`（深色科技）：深灰蓝背景，浅色文字，青蓝或琥珀作为小面积强调；
  必须保持高对比度，不使用霓虹光晕或渐变大色块。
- `soft-color`（柔和彩色）：暖白背景，低饱和鼠尾草绿、陶土色、雾蓝和浅紫用于分组；
  色彩只帮助区分，不改变事实含义。

## 事实与文字规则

- 姓名、身份、日期、金额、案号、原文引述和关系必须以输入原文为准。
- 不确定的信息标成“原文未明确”或直接省略，不得推测补全。
- 尽量用原文短语，长段落压缩为不改变含义的短句；引号内文字不得改写。
- 输出前逐项复核上述敏感事实，并检查文字是否截断、重叠或超出节点。

## SVG 安全与输出规则

1. 只写一个 UTF-8 SVG 文件。根元素必须是 `<svg xmlns="http://www.w3.org/2000/svg">`。
2. SVG 必须完全自包含：不得使用网络字体、外部图片、外部 CSS、脚本、`foreignObject`、
   事件处理属性或 `javascript:` URL。
3. 字体使用系统回退：`-apple-system, BlinkMacSystemFont, "PingFang SC",
   "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。
4. 所有样式、marker、pattern 和 defs 放在 SVG 内部；内部引用只使用 `#id`。
5. 最终回答不要输出解释，只向标准输出返回一份完整 SVG 并退出。
