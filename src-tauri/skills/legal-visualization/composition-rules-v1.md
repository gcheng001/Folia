## 进入 build_skill_visual_prompt v4 的 5 条编排约束

模型在生成结构 JSON 前,必须先以这 5 条自检;输出结构 JSON 时必须满足对应要求。

1. **一图一观点**——在结构 JSON 顶部输出 `main_view` 字段,值为一句不超过 40 字
   的"本图要证明/说明什么"。如果一句话写不清,说明图表任务还没有收敛,模型应
   拒绝输出并说明。
2. **颜色含义**——同主体或同类关系保持一致颜色;强调色(决策橙/争议红)只用于
   决策节点、争议事实、违约、风险、关键路径或己方主张;同一阵营或利益共同体用
   框架包围。
3. **缺失事实显式标注**——仅有对方陈述或待证事实时,必须把对应节点或关系标记
   `status: missing` 或 `status: asserted`(对应语义见 visual-constants-v1.md)。
4. **线型状态绑定**——`relations[].status` 五态(confirmed/disputed/asserted/
   inferred/missing)与上游视觉常量一一对应;不允许五态以外的值,缺省 = confirmed。
5. **3S 精简**——
   - Simple:节点文字用短词,合同全文/证据摘录/条文依据放侧栏或底注;
   - Straight:删除绕路支线,把主张、事实与法律后果连成不断点路径;
   - Strategy:为当前受众和当前立场保留信息(给法官保留可核对事实;给客户突出
     路径和风险;给团队保留证据缺口)。

## 四步流程(模型内部流程,不需要输出)

1. 明确对象(受众 → 表达重点);
2. 选择图表类型(时间/关系/数据/流程/空间,Folia 仅前 4 类);
3. 确定内容(全面罗列 → 逻辑整合 → 精简);
4. 更好表达(颜色/线条/框架/文字/布局/连线标签六维度)。

## 一图一观点(进入校验)

`main_view` 字段为字符串,长度 1-40 字(中文按 1 字计,英文按 1 词计);缺省或
超长时,前端在 VisualWorkbookPane 顶部以告警条提示。

## 客观与立场(进入校验)

诉讼图表可以有立场,但不能改变事实。Folia 端渲染层按下列规则视觉化:

- 已有材料直接支持的事实 → `confirmed`,实线,常规色。
- 仅一方陈述或待证事实 → `asserted`,虚线,主张方颜色,标签前缀「主张」;
  或 `missing`,灰色,标签前缀「待补充」。
- 双方主张并列时,用左右/上下对比或不同线型,不把己方主张画成唯一事实。
- 法律结论用「观点栏」或「结论栏」表达,不混入事实节点。
