## 二、每张图的具体评价

### 1. 法律文档一-时间轴-01.svg · 浅色正式

**它画什么**

来自 `hearing-realistic.md`，抽取 6 个案件进展节点（用工关系、交通事故、责任认定、调解与赔付、原告付款、起诉与开庭），横向排列成时间轴。深蓝灰为主色，暖白底，节点用圆形深红标记，标题用宋体强调正式感。

**视觉优缺点**

- 优点：版式稳重、节点清晰、深蓝配深红克制不跳；适合放在庭审材料或案件汇报里。
- 缺点：浅色正式本身信息密度低，当节点超过 6 个时卡片会被压窄；如果以后还要加 "刑事程序" 等节点，建议改为纵向或分组。

**事实是否忠于原文**

- 时间顺序是按法律常识整理的合理顺序，没有写死日期，因为原文多数日期字段是占位符。
- 金额 35,000 元 / 1,000,000 元 与原告主张 125,000 元 / 750,000 元均来自原文。
- 没有编造姓名、地点或具体条文编号。

**是否建议进入产品接入**

浅色正式本身很适合作为默认风格，但单独这一张不够说明问题，要看其他三张。

### 2. 法律文档二-流程图-01.svg · 简洁商务

**它画什么**

来自 `hearing-template.md`，把空白庭审模板的主要章节整理成庭审流程。图中覆盖模板 10 节中的 9 节，省略了不适合作为固定流程节点的“需补充事项”；同时补入“庭前准备”“最后陈述”“休庭 / 宣判”三个常规庭审框架步骤。举证质证拆为 4 个子步骤。纯白底、深灰蓝主色、蓝色辅助、商务克制。

**视觉优缺点**

- 优点：白色背景干净，步骤清晰，举证质证用虚线分组让"原告—被告—原告—被告"四次循环一眼可见。
- 缺点：节点是单列纵列，对超长文档略嫌单调；如果文档同时含多个子流程，可以考虑泳道。

**事实是否忠于原文**

模板章节与补充的常规庭审步骤已经在上文分别说明；图不是对 10 个二级标题的逐项照抄。

**是否建议进入产品接入**

适合作为"流程类"文档的默认渲染；空白模板用流程图表达比逐条空白占位符更友好。

### 3. 证据目录-关系图-01.svg · 深色科技

**它画什么**

来自 `evidence-directory.md`，把 4 项证据（采购合同、物流签收、对账确认单、情况说明）摆成四角，中心节点是原告主张的待证金额 1,286,430.75 元。证据之间用虚线表示时间先后（合同→物流→对账→情况说明），证据到中心用实线表示"证明指向"。深石板色底色、cyan / emerald / violet / amber 四色边框区分证据类别。

**视觉优缺点**

- 优点：四色边框让证据类别一眼可分；时间链和证明链用不同线型 + 不同箭头头区分。
- 缺点：深色背景对长中文阅读不如浅色背景舒服；不熟悉的用户会觉得"像技术架构图而非证据目录"。

**事实是否忠于原文**

- 案号（2026）沪0101民初1234号 直接来自原文。
- 4 项证据的名称、来源、时间、载体、证明目的均与原文一致。
- 1,286,430.75 元来自原文（对账确认单的尚欠货款金额）。

**是否建议进入产品接入**

适合技术类文档，不适合作为法律证据目录的默认风格；可以在"技术架构 / 系统说明"场景作为可选。

### 4. Folia架构-脑图-01.svg · 柔和彩色

**它画什么**

来自 `docs/ARCHITECTURE.md`，以 "Folia" 为中心，分四象限辐射展开：上方"渲染与编辑"（6 项：WYSIWYG、源码、HTML 阅读、Word 预览、HTML 演示、复杂表格锁）；右侧"模块结构"（services/、components/、app/、config/）；下方"技术栈"（Tauri v2、React 19、Vite 8、Vditor、CodeMirror、Tauri 插件、Astro）；左侧"设置与发布"（Settings、Word 导出预设、HTML 导出预设、自动更新、测试策略）。柔和米色底，桃粉 / 天蓝 / 鼠尾草 / 丁香四色圆角矩形分组。

**视觉优缺点**

- 优点：颜色克制不闹，节点用圆角矩形显得不硬，适合做产品对外介绍页。
- 缺点：4 个象限都有 5-7 个子节点，单图信息量大，远看会显得"散"；颜色浅，长时间盯看可能略有视觉疲劳。

**事实是否忠于原文**

- 所有模块名、版本号（如 Tauri v2.11.1、React 19、Vite 8、Vditor 3.11.2）均来自 `docs/ARCHITECTURE.md`。
- 没有杜撰文件路径或功能。

**是否建议进入产品接入**

对非法律文档（产品介绍、新人 onboarding）效果较好；不适合法律材料。

## 五、是否值得进入产品接入

把视觉、许可、产品定位合起来看：

| 维度 | 评价 |
|------|------|
| 视觉质量 | 比现有可视化更整齐、更正式；适合正式材料 |
| 风格覆盖 | 四种风格差异明显，能覆盖大多数使用场景 |
| 中文排版 | 本轮渲染检查中未再发现文字遮挡；仍需用户肉眼确认实际阅读体验 |
| 与 Folia 设计语言 | 浅色正式与 Folia 的"书卷气"最贴合；深色科技与 Folia 的暖调反差大 |
| 许可风险 | 上游为 MIT；接入时需锁定版本并保留版权与许可证文本 |
| 用户体感 | 非开发者用 4 种风格预览容易选择；但柔和彩色对法律材料不严肃 |

**建议路径**：

1. 用户肉眼比对后，如果觉得"明显比现有方案好"，再走产品接入。
2. 用户确认效果后，按 `license-and-source.md` 记录的版本与许可要求接入，禁止直接跟随上游 main 分支。
3. 第一版保留四种风格选择，默认使用“浅色正式”；“深色科技”更适合技术文档，“柔和彩色”更适合非法律文档。
4. 即使视觉过关，第一版也要保持静态成品，不要尝试逐个编辑图形元素（与 `docs/adr/0005-skill-rendered-visual-channel.md` 一致）。
