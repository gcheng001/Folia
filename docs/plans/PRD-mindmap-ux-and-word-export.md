# PRD — 脑图体验升级（根节点/主题/可编辑）+ Word 法律文书导出缺陷修复

- 日期：2026-07-11
- 来源：用户（执业律师）实测反馈，基于 v0.4.8（M-B 只读脑图画布）+ 肖永吉案鉴定式分析报告实际导出取证
- 触发标签：ready-for-agent
- 执行约束：单轮执行预算 40 分钟或额度上限，到点暂停并输出进度总结与待办

## Problem Statement

用户是执业律师，用 Folia 写鉴定式案例分析报告等法律文书，核心诉求是"MD 即源"：Markdown 是唯一事实源，脑图和 Word 都是它的视图。当前四个问题挡住了真实使用场景：

1. **脑图结构错误**：把案件分析报告转成脑图后，文档大标题（如"鉴定式案例分析报告"）和"目录"章节被平铺成一级节点，与"第一部分/第二部分/第三部分"并列。用户预期：大标题是根节点（即"文件名"位置），目录根本不该出现——脑图本身就是目录。
2. **脑图样式复杂**：当前节点样式（卡片、圆角、阴影等）过于复杂。用户偏好简洁直线条的经典脑图形态，且希望有彩色/蓝色/紫色/黑白等常见简单主题可自选。
3. **脑图只读**：用户的初衷是开庭时直接在脑图里做记录，实时同步回 Markdown 文件。当前只能看不能改，无法满足庭审场景。键位习惯：Enter 创建同级节点、Tab 创建下级节点。
4. **Word 导出缺陷**（肖永吉案 docx 实测取证，158 段）：
   - 22 个段落带字面井号（`#####`/`######`）——五、六级标题未被解析，整行按正文输出；
   - 60 个段落以全角空格 `　` 开头——源 MD 自带段首空格，导出又叠加首行缩进两字符，出现双重缩进；
   - 6 处法条引用（blockquote）被渲染成灰底（EAEAEA）9 磅小字——对法律文书而言法条是正文的一部分，不应是"代码块式"的底纹小字。

## Solution

从用户视角：

1. 转脑图时，文档大标题自动成为中心根节点；目录章节自动消失；各"部分"成为一级分支——结构与用户心智一致。
2. 脑图默认呈现简洁直线条样式（纯文字节点 + 细直线/折线连接），提供 4 套内置主题：彩色（按分支自动配色）、蓝色、紫色、黑白，一键切换，选择被记住。
3. 脑图节点可直接编辑：双击/F2 改文字，Enter 加同级，Tab 加下级，Shift+Tab 升级，Delete 删除；每次修改即时写回 Markdown 源文件，切回编辑模式看到的就是改过的文档。
4. 法律文书导出 Word：任何层级的标题都不再漏井号；段首多余空格被规范化（缩进只由模板控制）；法条引用以适合法律文书的样式呈现（仿宋、无底纹、与正文协调的字号、左缩进以示引用）。

## User Stories

1. As a 律师用户, I want 文档唯一的大标题在脑图中成为中心根节点, so that 脑图结构与"一份文件一个主题"的心智一致。
2. As a 律师用户, I want "目录"章节在脑图中被自动排除, so that 脑图不出现与自身功能重复的噪音分支。
3. As a 律师用户, I want "第一部分/第二部分/第三部分"等章节成为根节点下的一级分支, so that 我能一眼看到报告的骨架。
4. As a 律师用户, I want 没有大标题的文档以文件名作为根节点, so that 任何文档转脑图都有稳定的中心。
5. As a 律师用户, I want 脑图默认是简洁的直线条样式（纯文字 + 细线）, so that 视觉焦点在内容而不是装饰上。
6. As a 律师用户, I want 在彩色/蓝色/紫色/黑白四套主题间一键切换, so that 我能按场合（自用分析/庭审投屏/打印）选择合适外观。
7. As a 律师用户, I want 主题选择被持久记住, so that 每次打开不用重新设置。
8. As a 律师用户, I want 双击（或 F2）脑图节点直接编辑文字, so that 我能在脑图视图里修正表述。
9. As a 律师用户, I want 按 Enter 在当前节点后创建同级节点, so that 庭审中能快速追加并列要点。
10. As a 律师用户, I want 按 Tab 在当前节点下创建子节点, so that 我能就地展开细化某个争点。
11. As a 律师用户, I want 按 Shift+Tab 把节点提升一级, so that 记录时层级放错能立刻纠正。
12. As a 律师用户, I want 按 Delete 删除空节点或选中节点（带子节点时需确认）, so that 误建的节点能快速清理。
13. As a 律师用户, I want 脑图中的每次结构/文字修改即时同步回 Markdown 文件, so that 开完庭我的源文件已经是最新的，无需二次整理。
14. As a 律师用户, I want 脑图编辑与源码编辑往返后文档其余部分（正文段落、法条引用、表格等非标题内容）保持不变, so that 我敢放心在脑图里改而不怕破坏文书。
15. As a 律师用户, I want 编辑冲突有明确规则（脑图打开期间以脑图为准/切换时刷新）, so that 双视图不会互相覆盖丢内容。
16. As a 律师用户, I want 导出 Word 时五、六级标题被正确渲染为标题而不是带井号的正文, so that 鉴定式分析的深层论证结构在 Word 里可读。
17. As a 律师用户, I want 段首的全角/半角空格在导出时被剥离、缩进只由模板的首行缩进控制, so that 不会出现双重缩进或参差不齐的段首。
18. As a 律师用户, I want 法条引用（blockquote）在法律文书模板下渲染为仿宋、无底纹、字号与正文协调、左缩进的引用样式, so that 法条看起来是文书的一部分而不是代码片段。
19. As a 律师用户, I want 其他模板（非法律文书）的引用样式保持各自原有设计, so that 修复不破坏别的使用场景。
20. As a 律师用户, I want 以上所有行为对同一份肖永吉案报告可复现验证, so that 我能用真实案卷确认修复效果。

## Implementation Decisions

### A. 脑图解析（项 2）— 复用 parseMarkdown 接缝

- 根节点提升规则从"恰好一个 H1"放宽为："首个标题是 H1 且其前无其他实质内容（允许空行/frontmatter/注释）→ 该 H1 提升为根"，后续再出现 H1 时作为一级分支保留。原"多 H1 全平铺"行为仅在首标题不满足条件时保留。
- 目录排除规则：标题文本经 trim 后等于"目录"、"contents"、"table of contents"、"toc"（不区分大小写）的标题节点，连同其整个子树从脑图树中排除。排除只发生在脑图视图，不改动 Markdown 源。
- 序列化器（脑图 → MD）必须对被排除的目录节保持原样透传：目录内容在往返后不丢失。

### B. 脑图主题（项 3）— 新增一个主题定义接缝

- 新增主题定义模块：一个主题 = 节点样式（字体、字号、边框、底色）+ 连线样式（直线/圆角折线、线宽、颜色）+ 分支配色数组（彩色主题按一级分支轮转取色，其余主题单色系）。
- 内置 4 套主题：`simple-color`（彩色）、`simple-blue`（蓝色）、`simple-purple`（紫色）、`simple-mono`（黑白）。默认 `simple-mono` 或 `simple-blue`（实现时定夺，倾向最素的）。
- 所有 4 套主题共用同一种"简洁直线条"形态：无卡片阴影、无圆角大底色块，根节点可有轻量强调（加粗/描边）。现有复杂样式不保留为主题选项。
- 主题选择持久化到应用现有的用户偏好存储机制，跟随应用而非跟随单个文档。
- 切换入口放在脑图视图的工具条/右键菜单，不进入全局设置页。

### C. 脑图编辑与双向同步（项 4）— 以序列化器往返为唯一同步接缝

- 同步架构：脑图编辑操作作用于内存中的脑图树（MindMapDoc），每次操作后经由序列化器生成新的 Markdown 全文并写回编辑器文档模型（即"经由既有的 MD 单一事实源"，不做增量补丁协议）。编辑器的保存/自动保存机制原样负责落盘——脑图不直接写文件。
- 序列化器的非标题内容（段落、法条、表格、代码块）按行透传，保证往返无损；仅标题行由树结构重新生成。
- 键位（在脑图画布聚焦时）：
  - Enter：在选中节点后插入同级空节点并进入编辑态；
  - Tab：为选中节点插入首个/末尾子节点并进入编辑态；
  - Shift+Tab：节点升级（成为父节点的后继同级）；
  - 双击 / F2：编辑节点文本；Esc 取消，Enter/失焦提交；
  - Delete/Backspace（非编辑态）：删除节点，有子节点时需确认。
- 节点文本即标题文本：编辑节点等于改对应标题行文字；新建节点生成对应层级的标题行，正文内容归属跟随其标题移动。
- 视图一致性规则：脑图视图激活期间，脑图是写入方；切回源码视图时脑图状态丢弃、下次进入重新解析。不做双向实时合并。
- 折叠状态、选中状态属于视图状态，不写入 Markdown。

### D. Word 导出（项 5）— 复用既有 md→docx 转换接缝

- 标题解析范围从 1–4 级扩展到 1–6 级；5、6 级标题在文档结构上映射为 Word 的 Heading 5/6，样式上法律文书模板为其定义与 4 级协调的收敛样式（字号不大于 4 级、保持黑体系）。禁止任何层级的井号落入正文。
- 段首空白规范化：段落（含标题）文本在渲染前剥离行首的全角空格、半角空格、不间断空格组合；首行缩进完全交由模板的首行缩进配置控制。列表项、代码块内部不做剥离。
- 法律文书模板的引用（blockquote）样式改为：无底纹、仿宋_GB2312、字号与正文同档或小一档（不小于 12pt）、左缩进保留以示引用层次、行距与正文一致。其他模板的引用样式不动。
- 该决策只改法律文书 preset 的配置值与解析器的通用行为，不引入新的样式系统。

### E. 已完成、不入本 PRD 执行范围

- block-dangerous-git hook 已于本轮直接修复：普通 `git push` 放行，force/删除远端分支/reset --hard/clean 等破坏性模式仍拦截（已用 8 用例验证）。

## Testing Decisions

- 测试只断言外部行为：给定 Markdown 输入 → 断言脑图树结构 / 序列化输出 / docx XML 片段；不断言内部函数调用或中间状态。
- **脑图解析/序列化**（项 2、4 的核心）：沿用 mindmap 测试套的既有风格（内联 MD 字符串 fixture + 树结构断言 + pandoc 交叉验证惯例）。往返测试是最高接缝：`serialize(parse(md)) === md`（未编辑时逐字节等价），以及"编辑一个节点后，仅相关标题行变化、其余行逐字节不变"。
- **脑图主题/键位**（项 3、4 的交互层）：沿用 MindMapPane 既有组件测试风格，断言渲染出的节点/连线属性随主题切换变化、键盘事件产生正确的树变更与序列化调用；不做像素级快照。
- **Word 导出**（项 5）：沿用 docxXml 测试套风格（md 字符串 → 生成 XML → 断言 `w:pStyle`/`w:shd`/`w:ind`/文本内容）。三个缺陷各配红灯用例：H5/H6 输入断言无字面 `#` 且落在标题样式；段首 `　` 输入断言输出文本无前导空格且保留 firstLineChars；法律文书模板 blockquote 断言无 `w:shd` 底纹且字体为仿宋_GB2312、字号 ≥ 24 half-points ×? （≥12pt）。
- 全部改动跑全仓库既有测试基线，失败数不得高于基线（当前基线以 v0.4.8 提交时的 470 通过为参照）。
- 最终人工验收：用肖永吉案报告原文件重新导出并解包比对；用同一文件转脑图检查根节点/目录/主题/编辑往返。

## Out of Scope

- git hook 修复（已完成）。
- 脑图内编辑正文段落内容（仅标题级编辑；正文仍回源码模式改）。
- 脑图节点拖拽重排、跨分支拖动（键盘操作优先，拖拽留后续）。
- 自定义主题编辑器（只提供 4 套内置）。
- 脑图导出为图片/PDF。
- Word 导出的其他模板样式重设计（只修法律文书模板的引用样式与通用解析缺陷）。
- 实时协同/多窗口同时编辑同一文档的冲突合并。

## Further Notes

- 执行优先级（用户场景权重）：D（Word 导出，日常刚需）→ A（根节点，转换正确性）→ C（可编辑，庭审初衷但工程量最大）→ B（主题，观感）。
- C 依赖序列化器往返无损这一前提，A 的"目录透传"决策同样依赖它——两者共享同一批往返测试资产。
- 用户键位习惯明确源自 XMind 类工具（Enter 同级 / Tab 子级），实现时不要发明变体。
- 每轮代码改动沿用既有惯例：红灯先行、pandoc 交叉验证（解析器侧）、Codex 对抗复核后合入。
