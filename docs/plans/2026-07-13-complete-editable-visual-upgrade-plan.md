# Folia 可编辑可视化完整升级计划

日期：2026-07-13
状态：需求已确认，等待执行
目标版本：v0.12
执行方式：一次连续跑完，不在阶段之间等待人工审批

## 一句话目标

先从根上消除成品图的文字重叠，再把现有“成品脑图”、Markdown 脑图和一键可视化工作簿升级为可编辑、可恢复、可检查、可安全交付的一整套能力；旧 SVG 不丢弃，先原样保留，再升级出可编辑副本。

## 明天早上必须能做到什么

1. 打开用户提供的两份旧 SVG，原文件保持不变。
2. 一键生成可编辑副本，升级前的画面基本不变；识别不准的部分锁住，不乱改。
3. 当前文字重叠能被检测出来，并通过“修复重叠”只调整附近内容。
4. 可以改文字、拖方框、改大小、增删方框和连接线；方框移动后连接线跟随。
5. 可以多选、组合、对齐、等距分布、吸附，支持撤销、重做和历史版本。
6. 保存后关闭再打开，编辑状态仍在；旧原图和历史版本都还在。
7. 正式导出前自动检查重叠、越界、过小文字和可核对事实。
8. 能导出干净的 SVG、PNG、PDF；交付版不携带源文件路径、编辑历史或内部标识。
9. Markdown 脑图和一键可视化工作簿也获得适用的编辑、检查、样式和导出升级。
10. 可以进入原文—图表对照模式：左边实时编辑并保存 Markdown，右边独立编辑并保存图表，双方互相定位且不会相互覆盖。
11. 生产包构建成功，安装到 `/Applications/办案工具集/Folia.app`，并在安装后的真实桌面应用里跑完验收。

## 先解决的根因

现在重叠不是“某几个坐标调错了”，而是职责放错了：模型同时负责内容和最终像素坐标，但模型不知道本机实际字体宽度，也没有稳定的碰撞检查。因此必须改成：

```text
模型：内容、关系、重点、风格意图
                ↓
Folia：真实测字 → 自动换行 → 计算方框 → 排版 → 走线 → 碰撞检查
                ↓
          本地生成最终 SVG
```

模型给出的坐标只能作为建议。最终文字宽度、方框大小、位置和连线路径全部由 Folia 决定。

## 已确认的产品边界

### 本次包含

- 四类成品图：流程图、时间轴、关系图、成品脑图。
- 实用图形编辑：文字、方框、连接线、组合、对齐、样式、撤销、历史。
- 旧 SVG 升级为可编辑副本，原图永不覆盖。
- 局部修复重叠，以及用户主动触发的整图重排。
- 四种内置风格和用户自定义风格。
- 弹性画布和原尺寸、适合内容、A4、16:9 导出尺寸。
- 正式导出的视觉质量检查和有限事实核对。
- Markdown 脑图与可视化工作簿的共用能力升级。
- SVG、PNG、PDF 干净交付版。

### 本次不包含

- 钢笔路径、自由手绘、布尔运算、渐变/滤镜编辑器。
- 单个字的字体设置或专业排版软件级能力。
- 新增第五种图。
- 接入 `baoyu-infographic` 或其他新 Skill。
- 声称自动判断法律结论正确。
- 自动把图里的修改写回 Markdown。
- 覆盖旧 SVG、旧版本或当前已安装应用而不留回退副本。

## 技术方案

### 1. 一个 SVG，同时满足编辑和普通查看

可编辑 SVG 仍然只有一个文件：

- 普通看图软件读取正常的 SVG 图形。
- Folia 读取 SVG 内的 `folia-editable-visual` 元数据，恢复节点、文字、连接、锁定状态、来源和有限历史。
- 可见图形带稳定内部编号，便于把场景数据和画面对应起来。
- 场景格式有版本号、校验和、迁移器和严格校验；损坏时降级为只读，不猜测修复。
- 正式交付时删除元数据、源路径、历史、内部编号和 AI 过程信息。

### 2. 旧 SVG 的升级办法

升级分两层，优先保护旧版外观：

1. 先把旧 SVG 完整复制为新文件，原可见图形不重画，因此升级瞬间的画面与旧版一致。
2. 本地分析 `text/rect/path/line/polyline/circle/ellipse/polygon/g` 等安全元素。
3. 根据“文字是否在方框内、线端是否靠近方框、元素是否共同移动”等几何关系建立可编辑对象。
4. 识别有把握的内容变成可编辑对象；没把握的内容保持原图形并锁定。
5. 用户可把锁定部分指定为文字、方框、连线、组合或装饰；每次指定都可撤销。

升级器不执行脚本，不加载外部 URL，不接受 `foreignObject`，也不把 SVG 当 HTML 执行。

### 3. 排版和重叠修复

- 使用浏览器 Canvas 按真实字体调用 `measureText`，而不是按字符个数估宽。
- 中文按实际宽度换行；长英文、数字和案号提供可预测的断行规则。
- 方框先根据文字和内边距确定最小尺寸，再参与布局。
- 整图重排使用锁定版本的 `elkjs`，依图类型选择树形或分层布局和正交走线；依赖以精确版本写入 lockfile，运行时完全本地。
- 局部修复使用 Folia 自己的最小位移算法，只移动冲突附近且未锁定的元素，不调用整图重排。
- 每次布局后必须再次检查；不能用“移动了”代替“问题已经消失”。

### 4. 共用编辑核心，不强行统一画法

共用核心负责选择、命令、撤销、对齐、碰撞、样式、画布和导出规则，但保留两种画面适配器：

- 成品 SVG 使用原生 SVG 场景适配器，才能最大程度保留旧图外观。
- Markdown 脑图、结构总览、关系图和流程图继续使用 React Flow 适配器。
- 时间轴、矩阵和图表保留专用渲染器，只接入共用历史、检查、样式和导出管线。

这避免把旧 SVG 硬塞进 React Flow 后变样，也避免维护三套互不一致的撤销、检查和导出逻辑。

### 5. 保存和历史

- 旧 SVG 升级永远新建“可编辑”副本。
- 正常保存和自动保存更新可编辑工作副本。
- 保存采用同目录临时文件、刷新落盘、原子替换；失败时工作文件保持原样。
- 整图重排、AI 优化、风格整图应用前自动建立历史快照。
- 普通编辑使用有上限的命令历史，避免在 SVG 里无限膨胀。
- 用户可以另存新版本，所有版本均不覆盖。
- ExFAT 等不支持硬链接的文件系统必须通过现有回归测试。

### 6. 人工修改保护

用户改过的文字、位置、大小、颜色和连接关系会被标记为受保护：

- “优化当前图”默认不碰受保护内容。
- 用户可以明确取消保护，或只选择允许优化的对象。
- “重新生成”产生另一张新图，不覆盖当前图。

### 7. 原文同步和事实核对

- 改图默认不改 Markdown。
- 若能精确找到来源，提供“查看原文”和“同步到原文”。
- 同步前显示修改前后差异并再次确认；找不到精确来源时不提供自动同步。
- 姓名、日期、金额、案号和逐字引述可与 Markdown 做精确比较。
- 摘要、观点和法律结论只提示人工复核，不作自动真伪判断。
- 不一致项逐条确认；没有“一键全部忽略”。
- 找不到来源的旧 SVG 显示“未与原文核对”，但仍可编辑和保存。

### 8. 导出检查

草稿保存不被阻止。正式 SVG、PNG、PDF 导出前检查：

- 文字互相重叠或超出方框；
- 方框非故意重叠；
- 连接线穿过无关文字或方框；
- 内容超出画布；
- 按目标尺寸计算后字体小到不可读；
- 可精确核对的事实与来源不一致。

严重问题阻止正式导出。每个问题可以单独标记为有意设计；相关元素改变后，该例外自动失效。

### 9. 原文—图表对照模式

- 左侧源 Markdown 和右侧图表各自自动保存到自己的文件，使用独立保存队列和失败状态。
- 页面方向固定为左侧源 Markdown、右侧图表或交付预览；不提供左右交换，只允许拖动比例或临时只看一侧。
- 原文保存不触发图表逐字重画，只把图表标记为“待更新”；用户点击“更新图表”并预览变化后才应用。
- 主工具栏跟随当前点击的一侧切换；两侧顶部只保留文件名、保存状态和待更新提示。
- 两侧通过来源锚点互相定位；无法可靠对应时不做猜测跳转。
- “联动定位”默认开启，按来源关联跟随当前焦点侧；拖动和缩放时暂停，不使用滚动条百分比同步。
- “同步到原文”先等待原文保存队列完成，再展示差异并原子写入 Markdown。
- 对照页面最多两栏；右侧在“编辑图表”和“交付预览”之间原位切换，Word、HTML、SVG、PNG、PDF 均不再额外占用第三栏或遮挡原文。
- 退出交付预览后恢复图表的缩放、画布位置和选中状态。
- 每份 Markdown 记住上次使用的当前对照图；右侧下拉框列出关联图和版本及其同步状态，一次只显示一张。
- Markdown 通过“对照”进入，图表通过“对照原文”进入；缺少关联时仅要求打开或新建对应文件，再次点击退出并恢复原单页状态。
- 窄窗口自动改为“原文 / 图表 / 交付预览”单栏页签，拉宽后恢复双栏和原分栏比例，切换过程不重建编辑器。
- 右侧支持从空状态直接选择类型和风格并“开始生成”；生成中左侧 Markdown 始终可查看和编辑，右侧显示真实阶段、模型、等待时间和取消。
- 默认根据整篇文档生成；左侧存在有效选区时额外支持“根据选中内容生成”，并固定选区快照与来源范围。
- 选区生成默认创建独立图；“添加到当前图”是单独操作，应用前预览新增节点、关系和落点并自动保留历史。
- 右侧无图时显示完整生成卡片；已有图后只保留紧凑的快速更新和重新生成操作，低频参数按需展开，运行中提供真正取消。
- 未保存 Markdown 首次生成前先保存原文，成功后自动继续并默认把图表放在同目录；取消或失败不产生孤立图表。
- 离开对照或切换文档后生成任务继续后台运行，工具栏可返回任务；完成通知不强制切页，只有明确取消才终止。
- 多文档任务进入全局生成队列，一次只运行一个联网模型任务；等待项可查看、取消和调整顺序，本地编辑与导出不排队。
- 应用重启后运行项标记中断、等待项保留，但不得静默联网恢复；用户明确选择按原快照重试或按最新原文重新生成。
- 只在关闭前确实处于对照模式时恢复对照布局；否则保持单页。恢复当前图、分栏、页签和联动开关但不恢复临时选择，缺失文件降级并提示重绑。
- 对照模式的 `Command+S` 和工具栏保存同时排空两侧保存队列，但保持两文件独立成功/失败状态。
- 撤销重做跟随焦点侧且历史完全分离；图表批量更新作为单次命令，不连带撤销 Markdown。
- 生成完成后立即进入对照；用户在左侧修正文档后，可在右侧“更新当前图”或“重新生成新版本”，任何操作都不覆盖旧版本。
- 图表变化清单是可选功能，不得把长文档更新变成强制逐项审批；一键更新后显示处理摘要，并允许按需查看未自动处理的项目。
- “快速更新”作为默认主操作：自动应用可靠且未受保护的原文变化，保留手工修改和不确定冲突，结束后只显示数量摘要。
- 原文变化后本地实时标记受影响图形、已删除来源和新增内容数量，但不改变图表内容或布局；标记可关闭且不得导出。
- 每次生成固定使用开始时的 Markdown 快照；任务中途的原文修改不混入结果，完成后按内容指纹判断并标记“基于较早原文”。
- 已有图更新或重新生成时继续显示旧图，只在顶部展示生成进度；新结果完整且检查通过后才切换，失败或取消保持旧图不变。
- 首次生成完成直接显示；已有图的新版本完成后，仅在右侧空闲时自动切换，编辑、预览或已切图时只通知且先安全保存。
- 切图、更新和关闭前排空相关保存队列；保存失败停留当前内容并提供重试/另存为，退出对照本身不关闭文件。

## 连续执行顺序和内部门槛

### 阶段 0：保护现场和建立基线

- 记录当前分支、未提交改动和基线测试结果，不覆盖用户已有改动。
- 备份当前 `/Applications/办案工具集/Folia.app`。
- 把两份真实 SVG 复制到测试夹具区；测试永不修改桌面原件。
- 安装并锁定 `elkjs` 精确版本，更新 `package-lock.json`，确认离线构建可用。

通过条件：基线状态、应用备份和真实样本副本都可恢复。

### 阶段 1：先消灭重叠根因

- 新生成改为“结构数据 → 本地测字 → 本地排版 → 本地 SVG”。
- 完成真实文字测量、中文换行、节点最小尺寸、走线和碰撞检测。
- 对已有两份真实 SVG 建立重叠检测回归。
- 实现局部修复和显式整图重排。

硬门槛：两份真实样本的已知重叠能检测并修复；新生成的四类图不得带严重重叠进入成功状态。未通过时不进入“完成”状态。

### 阶段 2：可编辑 SVG 基础

- 完成场景格式、SVG 元数据、稳定编号、迁移和损坏降级。
- 完成文字、节点、连接线的增删改、拖动、缩放和自动跟线。
- 完成多选、组合、对齐、分布、吸附、缩放和平移。
- 完成撤销、重做、自动保存、原子写入和历史版本。

硬门槛：保存、关闭、重开后画面和编辑状态一致；模拟写入失败不损坏旧文件。

### 阶段 3：旧 SVG 升级

- 完成安全解析、几何识别、置信度和锁定元素。
- 完成用户重新分类和撤销。
- 初次升级保留旧投影，不因解析重画而改变外观。

硬门槛：两份桌面 SVG 原件未改变；升级副本在首次编辑前的截图差异不超过可见像素的 0.5%，或差异全部来自系统字体抗锯齿且人工截图对照无结构变化。

### 阶段 4：完整编辑、样式和画布

- 补齐节点/连接线样式、四种内置风格、自定义风格。
- 完成弹性画布、适合内容、原尺寸、A4 横竖版、16:9。
- 完成人工修改保护、“优化当前图”和“重新生成”。

硬门槛：应用风格不改变文字和结构；受保护内容在优化后逐项一致。

### 阶段 5：三个可视化入口一起升级

- 工具栏名称改为“Markdown 脑图”“一键可视化”“成品图”。

## 强制调试闭环

本次升级的每个阶段都必须执行同一套调试闭环，不能把问题留到最后统一处理：

1. **稳定复现**：记录准确输入、操作步骤、运行环境和实际结果；无法稳定复现前不盲改代码。
2. **缩小范围**：判断问题属于场景数据、测字、布局、画布、保存、生成队列、导出还是 Tauri 文件层，并用最小样本复现。
3. **提出单一根因假设**：每次只验证一个可证伪的原因，禁止同时堆叠多个猜测性修改。
4. **增加针对性观察**：使用断言、受控日志、测试探针或截图标记取得证据；日志不得泄露案件原文、绝对路径或模型内容。
5. **验证根因**：必须证明触发条件与故障存在因果关系；假设错误就退回重新分析。
6. **最小正确修复**：调试期间不顺手做无关重构，不用吞异常、延时加长或重试掩盖竞态。
7. **补回归测试**：先证明测试在旧行为下会失败，再确认修复后通过，并把测试加入相应阶段门禁。
