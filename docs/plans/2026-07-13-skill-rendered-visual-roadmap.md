# Skill 成品图升级路线

日期：2026-07-13。状态：第一版产品接入已完成代码、自动测试和浏览器视觉点验，等待真实 Claude Code 登录态完成桌面生成验收。第二版原范围已被用户扩展，实施以 [可编辑可视化完整升级计划](./2026-07-13-complete-editable-visual-upgrade-plan.md) 为准。术语见 `CONTEXT.md`，决策见 `docs/adr/0005` 至 `0020`。

## 为什么调整方向

现有 AI 可视化能理解文档并生成可编辑工作簿，但用户真机反馈是：生成效果不满意，界面和图形不够美观。继续增加本地模板或抽取规则不能直接解决视觉质量问题，因此新增一条以成品效果为先的 Skill 路径。

## 已确认的方向

- Skill 成品图与可编辑 `.foliaviz` 工作簿并存，不互相转换，也不互相替代。
- 第一版优先解决“生成得漂亮”，接受不能逐个拖动或编辑图形元素。
- 第一版只接入 `baoyu-diagram`，先覆盖流程图、时间轴、关系图和脑图等结构图。
- 第一版提供浅色正式、简洁商务、深色科技和柔和彩色四种风格，默认使用浅色正式；所有风格在生成入口旁直接提供，不把风格选择藏进设置页。
- 每份文档分别记住上次选择的风格；从未选择过风格的新文档使用浅色正式，不沿用其他文档的选择。
- 软件依据当前文档先推荐流程图、时间轴、关系图或脑图中的一种，同时在生成入口旁展示全部类型，用户可以在生成前改选。
- 风格由用户按文档用途选择；Folia 面向法律文档，但 Skill 成品图不限定只能处理法律文档。
- Folia 使用经过审查并锁定版本的 Skill，不直接执行用户机器上任意来源、任意版本的 Skill。
- 生成结果可以查看、导出和重新生成；重新生成必须保留旧结果。
- 第一版不做自动事实检查，也不阻止导出；用户自行核对结果，发现错误时修改原文或带纠错要求重新生成。
- 第二版增加手动编辑，让用户直接修正成品图里的文字和事实表达，修正结果另存新版本。
- 第二版继续只保存一个 SVG：普通软件直接显示成品，Folia 从同一文件恢复文字、方框、尺寸和连接关系，不增加并列工程文件。

## 前置验证：先证明效果值得做

第一步不是立即改完整产品，而是用真实法律文档做小范围对比试验：

1. 选择至少三份结构不同的真实文档，覆盖时间事实、人物关系和程序流程。
2. 使用同一份原文分别生成现有 `.foliaviz` 和 `baoyu-diagram` 成品图。
3. 分别验证浅色正式、简洁商务、深色科技和柔和彩色，避免只为法律文档优化。
4. 检查中文是否清楚、文字是否重叠或被裁切、事实是否忠于原文、整体是否明显比现有结果美观。
5. 确认 Skill 及其资源允许随 Folia 分发；许可不清楚时只做本机试验，不进入安装包。

只有用户确认成品质量明显提升，才进入应用内接入。这样可以避免先花大量时间接入，最后仍不满意。

## 第一版：接入 Folia 并生成静态成品

- 工具栏提供独立的“Skill 成品图”入口，不冒充可编辑工作簿。
- 生成入口旁显示可预览的风格选项；默认选中浅色正式，用户可以在生成前改选其他风格。
- 生成入口旁同时显示流程图、时间轴、关系图和脑图；推荐类型只是默认选中项，不替用户锁定结果。
- 再次打开同一文档时恢复该文档上次使用的风格；新文档仍回到浅色正式。
- 始终使用编辑器里的最新文档内容，不能悄悄读取旧的磁盘版本。
- 准确提示内容会交给 Claude 服务处理，不再声称“不会离开本机”。
- 生成期间显示当前阶段和等待时间，并提供真正可用的取消按钮。
- 先写临时文件，检查成功后再保存；已有同名结果时另存新版本，绝不提前删除或覆盖。
- 文件名使用“原文名称-图类型-版本号”，例如 `借贷纠纷-时间轴-01.svg`；风格不写进文件名，连续生成时版本号依次增加。
- 生成完成后自动在 Folia 中打开，可以另存和导出。
- 补齐按钮、失败、取消、旧文件保护和真实桌面点击链路测试。
- 不建设自动事实检查和导出拦截；界面只明确提醒用户在对外使用前核对成品内容。

## 第二版：增加手动编辑

- 用户可以直接修改姓名、身份、日期、金额、原文引述和其他文字，不必为小错误重新生成整张图。
- 用户可以移动方框和调整大小，已有连接线随方框自动调整，不需要手工重新对齐。
- 用户可以新增或删除方框与连接线，用于补充遗漏内容、移除多余内容和修正错误关系。
- 用户可以单独修改方框颜色和强调程度，也可以调整连接线颜色、粗细、实线或虚线以及箭头。
- 字体由整张图统一控制，不提供单个方框的任意字体设置，避免视觉风格失去一致性。
- 编辑信息保存在同一个 SVG 内；带 Folia 编辑信息的 SVG 直接进入编辑模式，普通旧 SVG 可在保留原件后升级为外观优先的可编辑副本。
- 手动修正只改变成品图，不自动改写 Markdown；需要改原文时由用户返回源文档修改。
- 编辑后的结果保存为新的成品图版本，原始生成结果继续保留。
- 提供“优化当前图”：保留用户手动修改的文字、位置、大小和局部样式，只优化未被手动修改的内容或用户明确指定的部分。
- 提供“重新生成”：忽略当前图的手动编辑，重新依据源文档、图类型和风格生成一张全新图。
- 两种操作都保存为新版本，当前图和更早版本不被覆盖。
- “优化当前图”和“重新生成”都允许附加一句话要求，例如“更正式”“减少文字”“突出争议焦点”。
- 重新生成可以调整布局、颜色、文字多少和突出重点，但不得擅自改变姓名、身份、日期、金额、原文引述和关系等事实。
- 保留每次生成的版本，允许回到上一个结果。
- 根据第一版反馈增加或淘汰风格，但继续保持少量、清楚、带预览的选择，不让用户面对复杂参数。
- 记录使用的 Skill 版本和生成要求，后续可以复现或比较效果。

## 第三版：增加更多 Skill

- 评估 `baoyu-infographic`，用于高密度信息图、对比图和视觉摘要。
- 只有 `baoyu-diagram` 的第一版静态生成和第二版编辑能力都稳定后，才开始接入 `baoyu-infographic`。
- 在接入信息图前先确定稳定的图片生成服务、费用、隐私提示和失败处理。
- 根据真实需求再评估幻灯片、卡片等其他 Skill；不为“Skill 数量多”而增加入口。
- 可考虑团队统一风格，但必须先解决 Skill 授权和版本升级问题。

## 更远期方向

- 支持选择部分文字生成，而不必每次处理整篇文档。
- 支持批量生成一组互相关联的成品图。
- 为成品图保留来源说明，便于核对事实，但不把静态成品强行解析回 `.foliaviz`。
- 成品图建设边界明确的实用图形编辑器，并与可编辑工作簿共用基础能力；不扩张为专业矢量美术软件。

## 明确不做

- 不直接执行用户机器上来源不明的任意 Skill。
- 不把 Skill 生成的 SVG、PNG 或 HTML 反向解析成 `.foliaviz`。
- 不用假进度百分比掩盖长时间等待。
- 不静默上传文档，不使用错误的“完全本地”提示。
- 不覆盖旧成品，不因本次生成失败而丢失以前的结果。
- 第一版不同时接入多个 Skill，也不加入复杂的模型和参数选择。

## 讨论结论

第一版、第二版和第三版的范围与先后顺序已经确认；后续实施按“前置验证 → 第一版静态生成 → 第二版可编辑 SVG → 第三版信息图”的顺序推进，不跨过前一阶段的验收门槛。

## 完成标准

第一版只有同时满足以下条件才算完成：

- 用户用真实案件文档确认视觉效果明显优于现有可视化。
- 浅色正式是默认风格，其他风格在生成入口旁可见、可预览、可切换，并至少用一份非法律文档验证。
- 同一文档能够恢复上次使用的风格，新文档不会错误继承其他文档的风格。
- 软件能给出一个图类型建议，用户也能在生成前清楚看到并改选其他类型。
- 中文无明显乱码、重叠、裁切或小到无法阅读的问题。
- 第一版不宣称自动保证事实正确，明确提醒用户在对外使用前核对内容。
- 生成使用当前最新内容，隐私提示准确。
- 可以看到进度并取消。
- 旧文件不会被覆盖或删除。
- 文件名不包含风格，按“原文名称-图类型-版本号”保存并依次保留。
- 失败后能够重试，且不会留下被误认为成功的损坏文件。
- 自动测试与真实桌面点验均通过。
