# 一键可视化工作簿实施计划

## 交付目标

在 Folia 中把现有脑图入口升级为离线“一键可视化”，生成独立可编辑的 `.foliaviz` 工作簿，覆盖六个视图家族、来源追溯、人工注释、增量同步及净化导出。

产品契约见 [PRD-one-click-visual-workbook.md](./PRD-one-click-visual-workbook.md)，术语见 [../../CONTEXT.md](../../CONTEXT.md)，架构约束见 [ADR 0002](../adr/0002-hybrid-visualization-renderers.md) 与 [ADR 0003](../adr/0003-declarative-visualization-templates.md)。

## Phase 1：工作簿协议与文件能力

- 定义 `VisualWorkbook`、`VisualSheet`、SIR、来源锚点、展示覆盖、视图注释、待确认项和版本迁移类型。
- 新增 `.foliaviz` 读取、校验、保存、另存为与自动保存服务；优先保存相对来源路径。
- 扩展文件对话框、拖放、会话标签和 Tauri 文件白名单/关联，支持 `.foliaviz`。
- 实现内存草稿、首次保存、dirty/关闭确认和来源重新绑定。
- 以恶意/损坏 JSON、旧 schema、丢失来源和路径越界建立测试。

## Phase 2：Markdown 解析、来源锚点与视图路由

- 建立一次解析、多抽取器复用的 Markdown block 模型，忽略 fenced code 中的伪日期和伪表格。
- 生成可校验来源锚点：原始摘录、摘录指纹、块类型与位置提示；实现失效检测和安全重定位。
- 定义视图注册表与数据契约；实现确定性匹配评分和解释对象。
- 实现六类信号探测器及首批法律模板规则。
- 建立 fixture：普通大纲、时间密集、人物关系、程序流程、证据矩阵、数字表格、混合文档、低置信文档和冲突文档。
- 固定高匹配直接生成与低匹配候选阈值，并用 fixture 防止规则漂移。

## Phase 3：工作簿外壳与入口迁移

- 将 Toolbar 脑图按钮升级为可视化 split-button：主操作自动路由，菜单手动选类型。
- 新增懒加载 `VisualWorkbookPane`，占据主编辑区；提供返回 Markdown、页签、推荐依据、待确认侧栏、保存和导出入口。
- 把现有 `MindMapPane` 适配为结构总览 renderer，保留节点编辑、自由连线、主题和历史能力。
- 工作簿状态接入标签会话、快捷键、i18n、无障碍键盘导航和 compact 窗口布局。
- 更新 `docs/DESIGN.md` 中的页面状态、视图模式和组件规范。

## Phase 4：六个视图 renderer

- React Flow 适配层：结构总览、关系网络、流程与决策，共享选择、布局、连线、注释和缩放协议。
- HTML 适配层：时间轴、矩阵与对比，共享单元格编辑、行列调整、卡片/表格切换和长文字布局。
- SVG 适配层：柱状、折线和饼图，共享数据编辑表与图形重绘；首版不引入运行时外部网络资源。
- 所有 renderer 实现统一命令：编辑、撤销/重做、查看原文、绑定/解绑、导出能力声明。
- 对长中文、空数据、超大节点数、循环关系和重复实体建立布局回归。

## Phase 5：编辑、原文修正与增量同步

- 普通编辑只写展示覆盖；新增内容默认为视图注释。
- 实现“同步修正原文”差异预览、锚点复核、精确回写与失败回滚。
- 复用文件监听，检测源指纹变化并生成新增/修改/删除/来源失效差异。
- 实现逐项/批量接受，保留布局与展示覆盖；来源失效元素支持删除、注释化和重新绑定。
- 明确工作簿自动保存与 Markdown dirty 状态的独立性，并覆盖崩溃恢复/关窗流程。

## Phase 6：统一导出与交付净化

- 建立 renderer-neutral export scene，导出树使用 Canvas-safe 的 hex/rgb 色值，不继承应用 `oklch()` 主题。
- 当前页 PNG；图形类当前页 SVG；当前页/整本 PDF；整本独立只读 HTML。
- PDF 多页按页签分页；时间轴/矩阵允许内容自然分页并重复必要表头。
- 导出前剥离绝对路径、指纹、内部 ID、撤销历史和隐藏原文；显式开启时只加入可见来源摘录。
- 对浅色/暗色应用主题、透明/白底 PNG、中文字体、超长内容和无来源注释建立回归。

## Phase 7：质量门禁与发布准备

- 单元测试：schema、迁移、解析、锚点、路由、抽取器、同步 diff、净化器、各 renderer 数据适配。
- 组件测试：工具栏入口、候选选择、页签、待确认、编辑语义、关闭确认、导出菜单。
- E2E：Markdown → 自动推荐 → 编辑 → 保存 `.foliaviz` → 重开 → 修改源文档 → 增量审阅 → 导出。
- 运行 `npm run typecheck`、`npm run lint`、`npm test`、`npm run build`；Tauri 真机验证文件关联、保存权限与 PDF/HTML 交付。
- 更新 `ARCHITECTURE.md`、`DESIGN.md`、`ROADMAP.md`、`TASKS.md`、`CHANGELOG.md` 和用户文档。

## 实施顺序与提交边界

每个 Phase 独立提交并保持主分支可构建。Phase 1～3 建立可打开、可保存、可生成结构总览的纵向闭环；Phase 4 按时间轴 → 关系网络 → 流程决策 → 矩阵对比 → 数值图表逐个接入；Phase 5 和 Phase 6 不与 renderer 大改混在同一提交。

## 完成门禁

- PRD 验收标准全部满足。
- 不回归现有脑图、WYSIWYG、Word/HTML 预览、文件监听和多标签会话。
- 所有新文件格式和导出路径均通过路径安全、内容净化和损坏输入测试。
- 没有网络请求、外部 Skill 执行或不可解释的推荐结果。
