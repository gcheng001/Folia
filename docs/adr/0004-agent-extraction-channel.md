# Agent 抽取通道：Folia 唤起本机 agent CLI 产出 .foliaviz，经宽容导入进入可编辑工作簿

已接受（2026-07-12）。可视化工作簿新增 **Agent 抽取通道**：Folia 以 Anything HTML 按钮的同等接口形态发起，headless 唤起用户本机已登录的编码 Agent CLI（首版仅 claude），携带随 Folia 版本发布的抽取规格；Agent 读取源 Markdown 后把 `.foliaviz` 写到源文档旁；Folia 经**宽容导入**接收——以原文摘录重新定位来源锚点、补算校验字段，定位成功的成为可追溯元素，失败的降级为待确认项。本地规则引擎保留并**冻结**：只修已知缺陷（如流程节点星号残留），不再扩充抽取规则。

本决策不推翻 ADR-0003：Folia 进程内仍不运行任何外部代码；智能抽取发生在应用外，Folia 只接收数据并逐条本地验证；抽取规格取代抽取规则代码，同样经代码审查、随应用版本发布。ADR-0003 中"确定性"的保证范围相应收窄为：本地引擎通道，以及任何已保存工作簿的渲染与导出；Agent 抽取本身不承诺两次生成结果一致。

**Considered Options**

- 继续加高本地规则引擎的天花板：关键词规则对任意法律文书的理解上限已被 v1 验证过低，属于军备竞赛式投入，拒绝。
- Agent 直接生成 HTML 成品（Anything HTML 现有玩法）：产物一次性、不可编辑、无来源锚点、无增量同步，重新生成时布局漂移，与工作簿模型互斥，拒绝作为工作簿路径（html-anything 继续承担 HTML 成品页交付，属平行产品线）。
- 把 Agent 生成的 HTML 反向解析回结构：等于再写一个不智能的解析器，且随模板改版即碎，拒绝。
- 借 html-anything 当宿主（自定义 skill 顺手写盘）：Folia 侧改动最小，但依赖 localhost:3000 服务在跑、自定义 skill 有被上游更新冲掉的风险、codex 沙箱写不出工作区，作为可能的二期入口而非首版。
- 派发给 MyAgents：两个桌面应用互相耦合，诊断链路最长，拒绝。

**Consequences**

- `.foliaviz` 从内部格式升级为**对外交换格式**：schema 需要一份供外部生产者遵循的规格文档；`parseVisualWorkbook` 需要导入模式——`excerptHash`/`start`/`end` 允许缺失，由 Folia 依据 `excerpt` 经 `resolveSourceAnchor` 补算（LLM 无法可靠计算哈希与字符偏移）。
- 新增失败模式需要 UI 状态：CLI 不存在或未登录、生成超时（建议 5 分钟）、产物校验失败；错误提示必须区分这三类。
- 隐私边界变化必须显性：走 Agent 抽取时源文档内容离开本机、经 Agent CLI 发往模型服务商；本地引擎通道保持零外发，两个入口在 UI 上不可混淆。
- 抽取质量的主要杠杆从代码转移到抽取规格（提示词）：规格迭代等同于旧规则版本升级，沿用 `rulesVersion` 语义标注产物来源版本。
